# AICamera Project Instructions

## Scope

These rules apply to this repository.

## Build and test

- Generate the Xcode project with `scripts/bootstrap.sh`.
- Run the full local validation with `scripts/validate.sh`.
- Version the camera extension independently of the host in `project.yml`, as with the audio
  driver. Host-only changes must not bump the component's build or marketing version. Bump the
  extension for changes to its source, resources/entitlements, shared protocol, or effective build
  settings. Keep source/staged/installed component-version checks separate from the host generation
  marker; do not restore a host/extension version-equality requirement. Ordinary host updates must
  retain the enabled extension and must not request extension activation.
- For normal UI development and acceptance testing, build a signed Release and install it at `/Applications/AI Camera.app`. Use the protected transaction generated by `scripts/install-app.sh` through this machine's approved passwordless `sudo` path so installation does not require repeated password entry. Verify the signed source and installed bundle, and do not replace the protected transaction with an ordinary recursive copy.
- Keep model endpoints, device IDs, signing teams, and credentials configurable.
- Never add real API keys or signing credentials to tracked files.
- Do not install or activate system extensions or audio drivers during automated tests.
- Treat camera and microphone buffers as private data. Do not persist them unless a user explicitly enables recording.

Read `AGENTS.local.md` when present for machine-specific signing and installation guidance.

## Architecture

- Keep media capture and rendering in the macOS host app.
- Keep the CoreMediaIO extension small. It only publishes host-produced frames.
- Keep model integrations behind protocols in `Sources/AICameraCore`.
- Real-time media paths must be bounded and must not wait for network inference.
- Update `PLAN.md` when non-trivial scope or status changes.
